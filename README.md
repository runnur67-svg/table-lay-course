# TABLE LAY — 크리스마스 코스 컨트롤 PWA v2 (태블릿 1대용)

**서버, PythonAnywhere, Firebase, 설치 프로그램, 로그인 PIN이 필요 없습니다.** GitHub Pages에 정적 파일을 올린 뒤, iPad(Safari) 또는 Android 태블릿(Chrome)에서 홈 화면에 추가해 사용하는 웹앱입니다.

이 앱은 2026년 12월 24일과 25일 **7개 회차**를 관리하며, 현재 사용 중인 컴팩트한 태블릿 가로 레이아웃을 유지합니다.

## 1. GitHub Pages에 게시하기

1. GitHub에서 **새 저장소**를 만듭니다. 예: `table-lay-course`.
2. ZIP 압축을 풀고 다음 파일/폴더를 **저장소 최상위 경로**에 업로드합니다.
   - `index.html`
   - `service-worker.js`
   - `static/` 폴더 전체 (`app.js`, `style.css`, 아이콘, 매니페스트)
   - `README.md`는 선택 사항입니다.
3. GitHub 저장소의 **Settings → Pages**에서 **Deploy from a branch**, `main`, `/ (root)`를 선택하고 저장합니다.
4. Pages에 표시되는 주소를 태블릿에서 엽니다. 일반적인 형태는 `https://계정명.github.io/table-lay-course/`입니다. **실제 주소는 GitHub Pages가 안내한 주소를 사용하세요.**
5. 최초 1회는 온라인 상태에서 접속해 페이지를 완전히 로드합니다. 앱 캐시 설치 후에는 네트워크가 끊겨도 실행할 수 있습니다.

> **중요:** ZIP 파일 자체를 GitHub에 올리기만 해서는 사이트가 실행되지 않습니다. 압축을 **풀고** 위 파일 구조를 그대로 올려야 합니다. GitHub Pages에서 `static` 폴더 구조가 변경되면 앱이 동작하지 않습니다.

## 2. 태블릿에 설치

**iPad / iPadOS**: Safari에서 Pages 주소를 연 뒤, 공유 메뉴에서 **홈 화면에 추가**를 선택합니다. 만들어진 아이콘으로 앱을 열어 사용합니다.

**Android 태블릿**: Chrome에서 Pages 주소를 연 뒤, 브라우저 메뉴의 **앱 설치** 또는 **홈 화면에 추가**를 선택합니다.

- 가로 방향으로 사용하세요.
- 처음 한 번은 인터넷 연결 상태에서 앱을 열어야 오프라인 실행용 파일이 캐시됩니다.
- 태블릿에서 인터넷을 끈 상태로 홈 화면 아이콘을 실행하여 오프라인 작동을 미리 확인해 보세요.
- GitHub Pages는 **사이트 파일만 제공**합니다. **매장 데이터는 태블릿에만 보관**되며 GitHub에 올라가지 않습니다.

## 3. 운영 기능

- 실제 POS 배치 그대로: **대기 1 / 대기 2**, 중간 **10·9·8·7·6**, 아래 **5·4·3·2·1**
- 2026년 12월 24일: 런치 1부, 디너 1·2부 / 25일: 런치 1·2부, 디너 1·2부
- 회차별 완전 독립된 테이블 진행 상태 및 예약 인원(1~12명), 알레르기 확인 상태와 상세 사항
- 테이블 등록 즉시 **앞으로 제공할 모든 코스의 남은 요리 수량** 합산
- `1인당 1개` / `테이블당 1개` 수량 기준을 각 코스별로 설정 가능
- 각 테이블의 코스 시작, 서빙 완료, 이전 코스로 복구, 테이블 비우기
- 타이머 자동 갱신 및 정상/임박(5분 이내)/지연 상태 강조
- 실제 데이터와 분리된 연습 모드 및 시간 ±5분 시뮬레이션
- **런치·디너 공통 코스 편집**: 요리 이름 / 순서 / 코스 수 / 수량 기준을 수정하면 같은 식사 유형의 모든 회차에 적용
- **7개 회차별 독립 시간 설정**: 각 회차의 예정 시작, 종료, 개별 코스 제공 분을 서로 다르게 설정
- **7개 회차별 타임테이블 보기**: 회차별 표, PNG 이미지 공유·저장, 인쇄/PDF, 텍스트 복사
- 중요한 내용은 **IndexedDB**로 매 변경 시 자동 저장; 변경 성공 후 상태 표시
- 설정 → **전체 데이터 백업 (.json)** / **백업 복원 (.json)**

### 남은 요리 수량 규칙

- 이번 회차에 **등록된** 테이블만 합산합니다. 착석 전이라도 등록된 예약 인원은 계산에 포함됩니다.
- 아직 제공하지 않은 **현재 코스부터 마지막 코스까지** 모두 계산합니다.
- 예: 3인 테이블의 스테이크가 `1인당 1개`라면 3개. `테이블당 1개`면 1개.
- 서빙 완료를 누르면 **방금 제공한 코스**의 수량이 즉시 합계에서 제외됩니다.
- `지금 N개`는 현재 차례의 요리가 예정 시각에 도달한 테이블들의 수량입니다.

## 4. 코스 구성과 회차별 시간 편집

상단 **⚙ 설정**을 누르면 두 개의 편집 탭이 있습니다.

### A. 런치·디너 코스 구성 (공통)

1. **① 런치·디너 코스 구성**에서 런치 또는 디너를 선택합니다.
2. 코스명, 순서(코스 삭제 후 다시 추가하는 방식), 코스 수, 수량 기준(`1인당 1개`/`테이블당 1개`)을 정합니다.
3. **공통 코스 구성 저장**을 누릅니다.
4. 런치의 경우 **24일 런치 1부, 25일 런치 1·2부**에 함께 반영됩니다. 디너는 **24일 디너 1·2부, 25일 디너 1·2부**에 반영됩니다.

코스 구성을 저장해도 **기존 각 회차의 시작 시각은 유지**됩니다. 기존 코스들의 경과 시간을 최대한 보존하고, 추가된 코스는 임시 경과 시간으로 설정하므로 필요하면 다음 단계에서 세부 시간을 편집하세요. **이미 서빙 중인 회차가 있다면 코스 수의 변경을 차단**하여 테이블 진행 데이터와 코스 단계가 어긋나지 않도록 합니다. 코스 이름이나 수량 기준은 수정할 수 있습니다.

### B. 7개 회차별 서빙 시간 (개별)

1. **② 회차별 서빙 시간** 탭으로 이동합니다.
2. 회차(예: `12월 24일 · 런치 1부`)를 선택합니다.
3. **예정 시작 시각**, **종료(시작 후 분)**, 코스별 **시작 후 경과 분**을 설정합니다.
4. 입력 옆에서 계산된 실제 시각을 확인한 뒤 **이 회차 시간 저장**을 누릅니다.
5. 다른 회차를 선택해 각 회차에 맞는 시간을 설정합니다.

예: 24일 런치가 `12:00`에 시작하여 스테이크를 `+47분`에 제공한다면 `12:47`, 25일 런치가 `11:45` 시작에 스테이크를 `+52분`에 제공한다면 `12:37`로 계산됩니다. **요리 구성은 같고 시간표만 다른 구조**입니다.

**메인 현황과 수량 연동:** 공통 메뉴명·수량 기준을 바꾸면 테이블 카드와 상단 남은 요리 수량에 바로 반영됩니다. 각 회차의 제공 간격을 바꾸면 해당 회차의 테이블 서빙 예정 시각과 카운트다운에도 반영됩니다. 다만 메인에서 개별 테이블의 실제 타이머 기준은 항상 해당 테이블에서 누른 **첫 코스 시작 시각**입니다. 회차의 예정 시작 시간은 타임테이블 및 메인 상단의 안내값입니다.

### C. 회차별 타임테이블 표 / 공유

1. 메인 상단의 **▦ 타임테이블** 버튼을 누릅니다.
2. `24일 런치 1부`, `25일 디너 2부` 등 **7개 회차 중 하나**를 선택합니다.
3. 각 코스의 **서빙 시각, 시작 후 경과 시간, 코스명, 수량 기준, 종료 시각**을 표로 확인합니다.
4. 팀원에게 전달하려면 **이미지 저장·공유**를 누르세요. 지원하는 태블릿은 공유 메뉴가 열리고, 그렇지 않으면 PNG 파일을 저장합니다. **인쇄 / PDF**는 브라우저의 인쇄 화면을 사용합니다. **텍스트 복사**도 제공됩니다.

회차 시작 시각을 확정하지 않았다면 표에는 `미정`으로 표시되며, 분 단위 경과 시간은 계속 볼 수 있습니다. **표는 마지막으로 저장된 설정**을 기반으로 생성됩니다.

## 5. 자동 저장, 백업, 복원

**자동 저장**: 코스 진행, 예약 인원/알레르기, 회차 설정을 바꾸면 그 즉시 태블릿 브라우저의 IndexedDB에 저장합니다. 새로고침하거나 홈 화면 앱을 닫았다 열어도 기록이 유지됩니다.

**백업**: `⚙ 설정 → 전체 데이터 백업 (.json)`을 누릅니다. 7개 회차의 메뉴 설정과 진행 상태를 한 파일로 저장합니다. iPad에서는 다운로드한 파일을 **파일 앱**, iCloud Drive 등의 안전한 위치에 보관하세요.

**복원**: `⚙ 설정 → 백업 복원 (.json)`에서 저장한 JSON 파일을 선택합니다. 내용을 검증한 뒤 전체 덮어쓰기를 확인합니다. **7개 회차 전체를 복원하므로 현재 내용을 먼저 백업**하세요. 잘못된 파일이나 지원하지 않는 형식은 거부합니다.

**주의**:

- Safari/Chrome의 **사이트 데이터 삭제**, 앱 제거, 저장 공간 정리, 기기 교체 시 IndexedDB 데이터가 사라질 수 있습니다. 특히 iOS에서는 장기간 사용하지 않거나 저장 공간이 부족할 때 데이터 보존을 보장할 수 없습니다.
- 데이터는 **태블릿과 해당 브라우저 환경별로 별개**입니다. 같은 GitHub Pages URL을 다른 태블릿에서 열어도 코스 진행 상태가 동기화되지 않습니다.
- 백업 JSON에는 예약 인원과 알레르기 정보가 포함되므로 **GitHub의 공개 저장소에 백업 파일을 올리지 마세요.**
- 앱 소스는 GitHub Pages에서 공개될 수 있습니다. 하지만 **알레르기 및 코스 진행 내용은 소스 파일에 포함되지 않습니다.** 로그인 PIN은 없는 오프라인 단말형 앱입니다.

## 6. 코스 확정 전 확인

- **런치**: 임시 7코스 예시가 입력되어 있습니다. 정식 코스가 정해지면 [설정]에서 변경하세요.
- **디너**: 이전에 제공받은 9코스 타임라인을 바탕으로 입력했습니다. 실제 구성과 시간이 정해지면 수정하세요.
- **회차별 시작 시각**: 아직 미설정입니다. 각 테이블 타이머는 첫 코스 제공 버튼을 누른 실제 시각부터 시작합니다.
- 이미 서빙이 시작된 회차가 있다면 **코스 수 변경만 제한**됩니다. 시간 변경은 가능하며 즉시 현황판에 반영됩니다.

## 7. 파일 구성

```text
Table_Lay_Course_Control_PWA/
├── index.html                 # 태블릿 화면
├── service-worker.js          # 오프라인 실행용 캐시
├── static/
│   ├── app.js                 # 코스 컨트롤 + IndexedDB + 백업/복원
│   ├── style.css              # 가로 태블릿 UI
│   ├── manifest.webmanifest   # PWA 등록 정보
│   ├── icon.svg
│   ├── icon-180.png           # iPad 홈 화면 아이콘
│   ├── icon-192.png
│   └── icon-512.png
└── README.md
```

**GitHub Pages의 HTTPS가 필요합니다.** 파일을 태블릿에서 직접 열거나 `file://`로 실행하면 서비스 워커 설치가 되지 않으므로 오프라인 PWA로 사용하기 어렵습니다.

### 업데이트할 때

GitHub에 `index.html`, `app.js`, `style.css` 등을 업데이트해도 **동일한 사이트 주소**를 사용하고 사이트 데이터를 지우지 않는 한 IndexedDB 자료는 유지됩니다. 오프라인 캐시를 확실히 갱신하려면 새 버전 배포 시 `service-worker.js`의 `CACHE_NAME` 문자열도 바꿔야 합니다.

배포 뒤 업데이트할 때는 중요한 회차 데이터를 먼저 JSON으로 백업하고, 태블릿에서 온라인 상태로 새로 열어 업데이트를 확인하세요.

### 기존 v1에서 업데이트하기

기존에 같은 GitHub Pages 저장소로 운영 중이면 이번 버전의 파일을 **같은 위치에 덮어 업로드**하세요. 이 버전은 기존 v1 IndexedDB 저장소 이름을 그대로 사용하므로 업데이트 때 기존 7개 회차의 진행 내역을 보존하도록 설계했습니다. 이전 JSON 백업(v1)도 복원할 수 있으며, 새로운 백업은 v2 형식으로 저장합니다. **업데이트 전에는 반드시 v1에서 JSON 백업을 먼저 내려받으세요.**

새 버전의 `service-worker.js`는 캐시 이름이 변경되어 온라인 재방문 시 새 정적 자산이 설치됩니다. 홈 화면 설치 PWA에 예전 화면이 남는다면 인터넷에 연결한 상태에서 앱을 닫고 다시 실행해 보세요. 브라우저의 사이트 데이터 삭제는 하지 마세요.
