# TABLE LAY 코스 컨트롤 v3 — 기존 GitHub Pages 업데이트

기존 주소: **https://runnur67-svg.github.io/table-lay-course/**  
GitHub 저장소: **https://github.com/runnur67-svg/table-lay-course**

## 1. 업데이트 전: 현재 데이터 백업

1. **기존 앱을 쓰던 같은 태블릿·같은 브라우저**에서 웹앱을 엽니다.
2. `실제 운영` 모드인지 확인한 다음, `⚙ 설정 → 전체 데이터 백업 (.json)`을 누릅니다.
3. JSON 파일을 다운로드 또는 파일 앱의 안전한 위치에 보관합니다. **알레르기 정보가 포함된 백업을 공개 GitHub에 올리면 안 됩니다.**

## 2. GitHub에 수정 파일 올리기

1. 별도로 제공된 `Table_Lay_Course_Control_v3_UPDATE_ONLY.zip`을 **PC에서 압축 해제**합니다.
2. GitHub 저장소의 **Code → Add file → Upload files**를 엽니다. 직접 주소: `https://github.com/runnur67-svg/table-lay-course/upload/main`
3. 압축 해제한 폴더의 **`index.html`, `service-worker.js`, `static` 폴더**를 업로드 영역으로 드래그합니다.
4. GitHub 화면의 파일 경로가 다음과 같은지 확인합니다.

```text
table-lay-course/
├── index.html                   (기존 파일 교체)
├── service-worker.js            (기존 파일 교체)
└── static/
    ├── app-v3.js                (새 파일)
    ├── style-v3.css             (새 파일)
    └── manifest.webmanifest     (기존 파일 교체)
```

> 이전 `static/app.js`, `static/style.css`는 GitHub에 남아 있어도 괜찮습니다. **v3은 새 이름(`app-v3.js`, `style-v3.css`)을 읽으므로 캐시가 이전 파일을 잘못 보여주는 문제를 줄였습니다.**

5. 페이지 하단에서 **Commit changes**를 누릅니다.
6. GitHub 저장소의 **Actions**에서 가장 최근 `pages build and deployment`가 **초록 체크**인지 확인합니다. GitHub Pages 설정은 다시 할 필요가 없습니다.

## 3. 태블릿에 새 화면 적용

1. 태블릿에서 와이파이를 켜고 **기존에 사용하던 같은 브라우저**로 엽니다.
2. 주소는 바뀌지 않습니다: `https://runnur67-svg.github.io/table-lay-course/`
3. 새로고침합니다. 새 PWA 파일이 준비되어 알림이 뜨면 **`업데이트 적용 ↻`**을 누릅니다.
4. 새로고침했는데 이전 검은 화면이 남아 있으면 앱/브라우저 탭을 닫고 **다시 열어 한 번 더 새로고침**하세요. 새 파일에는 캐시 충돌 방지를 위한 새 경로가 적용되어 있습니다.
5. 화면이 **밝은 웜그레이 배경 + 흰 테이블 카드**로 바뀌고, 이전 7개 회차의 설정과 등록 테이블이 남아 있는지 확인합니다.

**중요:** 업데이트를 위해 삼성 인터넷/사파리의 **사이트 데이터 삭제**, **캐시 및 데이터 전체 삭제**, 홈 화면 앱 제거를 하지 마세요. 그러면 IndexedDB 운영 데이터가 사라질 수 있습니다.

## 4. 앞으로 버전 업데이트를 확인하는 방법

- 화면 **하단 오른쪽 `업데이트 확인`** 버튼: 인터넷이 연결된 상태에서 GitHub Pages에 새 서비스 워커 파일이 있는지 확인합니다.
- 새 버전을 다운로드하면 하단에 **`업데이트 적용 ↻`** 알림이 나타납니다.
- 편집 중인 코스 설정을 저장한 후 버튼을 누르면 새로고침하면서 적용됩니다.
- 이전과 동일한 **IndexedDB (`tablelay-course-pwa-v1`, `service-data`)**를 사용하므로 디자인 업데이트가 운영 데이터를 의도적으로 지우지 않습니다.

## 5. 달라진 디자인

- 다크차콜 → **라이트 테마**
- 메인 코스명, 남은 시간, 인원수 **확대**
- 지연은 빨간색, 임박은 황금색, 정상은 초록색으로 **가독성 향상**
- 알레르기는 경고 바탕으로 구분, 미등록 테이블은 차분하게 표시
- 요리별 남은 수량은 작은 가로바, 10개 테이블은 **POS 배치 그대로 5개×2줄**
- 런치/디너 공통 코스, 회차별 시간표, 연습모드, 백업/복원 기능 **유지**

## 저장 구조와 주의 사항

GitHub Pages에는 HTML/CSS/JavaScript 등 **앱 파일**만 게시됩니다. 고객 인원, 알레르기, 서빙 기록 등 실제 운영 정보는 **해당 브라우저의 IndexedDB**에 저장됩니다. 다른 기기와 자동 동기화되지 않습니다. 홈 화면에서 실행한 PWA와 브라우저 저장 영역이 분리되는 환경도 있으므로 반드시 실제 사용 방식에서 기존 데이터가 보이는지 확인하고 백업을 보관하세요.
